# Canvas text styling

Status: complete.

## Scope

Implement [Text block font size](../specs/interaction-model.md#text-blocks) and [shape label styling](../specs/interaction-model.md#shape-text). There is no pre-placement Text panel, shape creation default, rich text for shapes, or change to the Markdown source font family or color.

## Design

- **Document and history.** Add an optional `fontSize` override to `TextNodeStyle` and optional `labelFontSize`, `labelFontFamily`, and `labelColor` overrides to `ShapeElementData`. Resolve missing sizes to 14 and 13 respectively, a missing shape font to the bundled body font, and missing label color to the saved outline color. Keep absent overrides out of JSON so untouched canvases retain their canonical representation and GitHub baseline. Use one preset list for the dropdowns and validation. Reject sizes outside that list and blank font names at the document boundary; decode label color with the existing optional ARGB converter. Do not require font names to be in the catalog. Update copying, equality, hashing, document validation, and the generated codec.
- **Saved edits.** Keep writes in `EditorSession`. Use `setTextStyle` for Text size and add `setShapeLabelStyle` for label changes, separate from drawing options. Read the current element and change only the requested field. Keep style changes separate from typing in canvas history without ending editing or promoting the object. A no-op adds no history entry. Use the existing color control's change behavior and a separate **Use outline color** action.
- **Controls and focus.** Reuse `Select` for size, `SearchableSelect` and the font catalog for families, and `ColorControl` for label color. `CanvasPage` binds the active object and history callbacks; element panels lay out their controls. Cancel pending canvas recognition at the panel boundary, but end editing on pointer-down only in the legacy groups: shape drawing controls, Text Font, and Text Color/Background. Put the new controls in their editor's tap region. Committing a dropdown choice returns focus to the still-open editor at the same caret or selection; cancellation retains normal menu focus behavior. Return focus when the font choice is made, not after the download. Do not steal focus from the custom color picker. Keep the options tray's existing scroll boundary.
- **Font loading.** Share the existing picker and its request lifecycle between the two panels. Give it the target session and ID, a callback to read the current requested family from the live target, and a callback to apply a loaded family to the latest value. Use the pending request token to drive progress and disabled state. Invalidate immediately if the shape label becomes blank, even if text returns before the font loads. Verify the target, family, activation, and restoration state again before applying a completion; a stale completion cannot write or clear newer progress. A failed request leaves the current style in place and reports the existing font-load error. For saved shape fonts, load through the theme font cache when a styled label is visible and redraw on success; the bundled font covers loading, missing catalog entries, and failures.
- **Rendering.** Drive the Markdown source and preview from the same saved base size. Keep the source monospaced; scale the preview's existing text sizes from their current 14-based values using the Markdown stylesheet, leaving non-text decoration unchanged. Build one resolved label `TextStyle` in `ShapeElementView` for both the native editor and preview; leave shape geometry, clipping, and overflow behavior alone. Style changes must not recreate retained controllers, scroll state, or Markdown image resources.

## Steps and verification

1. Add saved fields, regenerate `canvas_document.g.dart`, and wire session operations. Extend document and history tests for unchanged legacy JSON, round trips, invalid values, no-ops, and undo/redo independent of typing. Exercise copy/paste with the new fields using the existing canvas clipboard path.
2. Wire the controls, focus behavior, and rendering. Update the annotated tool-options preview to show a labeled shape. Extend Text and shape browser widget tests to cover rendering in both modes, typing at the preserved caret after a choice, dismissal by legacy controls, conditional controls, clearing and retyping during a font load, outline color inheritance and reset, selection not tinting the label, font fallback and stale requests, and unchanged shape bounds. Cover mouse and keyboard interaction with the new controls.
3. Run focused Chrome tests, `flutter analyze`, and `flutter build web`. Check the options tray in Chrome at a short window height and verify the preview on a small shape at size 48. Run the full Chrome suite before committing.

## Verification result

Chrome widget tests covered the short options tray, size 48 on a minimum-size shape, and editor focus during font search and color entry. The first full run found a context-menu regression: the hidden Markdown placeholder was sizing a nonempty editor. After removing that layout contribution, all 160 tests in the Text and Arrange suites passed. After rebasing onto `main`, the full Chrome suite passed with 832 tests and four skips. Static analysis and the JavaScript web build passed.
